# A 部分 · 状态精灵（交付美术）

## A0. 一句话

**一只塔奇克马，一个循环，12 帧；五档状态由"节点色环 + 取几帧"表达，不由配色和姿态表达。**

美术只画一只塔奇克马的一个循环。状态色是工程侧画在节点上的环，**不需要美术出 5 套配色，也不需要出 5 套姿态**。

## A1. 画布与像素网格

| 项 | 值 | 为什么 |
|---|---|---|
| 单帧画布 | **32×32 像素**（1 画布像素 = 1 CSS px） | 图节点槽就是 32×32，1:1 不用缩放，最干净 |
| 像素网格 | 1:1，不画半像素 | 放大靠 CSS 整数倍，不靠画细节 |
| 出现在哪 | **派遣网络图的节点槽**（32×32 方形，圆角 4）+ **仪表盘卡片**（64×64 = 整数 2× 放大） | owner 定：精灵**不进成员表头像位** |
| 成员表头像是谁 | 头像 = **由会话目标派生的名字/角色**（不是精灵）；头像**右下角**一个 5 色小圆点表状态 | 头像是"这个人叫什么"，精灵是"这个成员累不累" |
| 安全区 | 圆角 4px 只切掉一点点，主要识别特征放在中心 28×28 内 | 保险起见 |
| **禁止** | 30×30 / 48×48 / 96×96 这类非 32 整数倍的母版；导出时用 Aseprite `--scale` 缩放 | 非整数缩放必然插值发糊 |

## A2. 状态 → 动画映射表

五档配色（固定 hex，工程侧画成节点色环/底色）：

| 档位 | tag | 判据（上下文窗口占用 = `used / size`） | 色环 hex | 取几帧 | 一个循环周期 |
|---|---|---|---|---|---|
| **空闲** | `idle` | 没有在跑的会话 **或 拿不到占用数据** | 蓝 `#58a6ff` | 6 / 12 | T |
| 轻松 | `easy` | `< 10%` | 绿 `#3fb950` | 6 / 12 | T |
| 累了 | `tired` | `≥ 10%` | 黄 `#d29922` | 9 / 12 | T |
| 超累 | `exhausted` | `≥ 20%` | 橙 `#f0883e` | 9 / 12 | T |
| 要累死了 | `critical` | `≥ 40%` | 红 `#f85149` | 12 / 12 | T |

- **阈值可调**，默认 `10 / 20 / 40`。
- **必须同时记录窗口大小**（`size`，1M 是主流默认）：同为 10%，200K 窗口和 1M 窗口是完全不同的处境。UI 上要显示窗口。
- **拿不到占用数据 → 按 `idle` 蓝渲染并继续循环**（owner 口径："没停顿"）。不引入"未知档"，不出现静止态。
- **只做循环小动**（呼吸；眨眼可作为循环内的一小段），不做状态切换的一次性动画（#9 已定）。
- 不按档位改姿态（"越累越蔫"是 P1 可选，非必须）。

## A3. 循环方式与帧率

**硬约束（owner 口径）**：所有档位**共用同一个循环周期 T**；各档**帧数不同**，取 `6 / 9 / 12`（都是 **36 的因数**）。

- 公共时钟 = `T / 36`（默认 T = `1.2s` → 每格 ≈ `33.3ms`）。因为 `6 / 9 / 12` 都整除 36，**每档的帧切换都正好落在公共时钟的刻度上** → 同屏所有精灵在每个 T 边界**相位重新对齐**，不会出现"某个精灵在别人切换到一半时切换"这种视觉不同步。
- 每帧时长 = `T ÷ 帧数`：12 帧 → `100ms`；9 帧 → `133.3ms`；6 帧 → `200ms`。有效帧率 `5 – 10 fps`，都在像素风惯例区间内。

| 项 | 值 |
|---|---|
| 母版帧数 | **12 帧**（一个完整循环） |
| 其他档怎么来 | 播放器从这 12 帧里按档位取子集（12 = 全取；9 = 按最近邻取 9 帧；6 = 每隔一帧取 6 帧）。**美术不用出多套帧数** |
| 可选（P1） | 若美术愿意，把 9 帧那档单独画一支，节奏更准 |
| 可选（P1） | 加一支 `blink` tag（12 帧，周期 `4 × T`）做"活着"的细节 |
| 循环 | 必须无缝（首尾帧接得上） |

**帧率由我们的数据（T + 帧数）决定，不由美术导出时的帧率设置决定。**

## A4. 导出格式与命名

**交付三件**：

1. `tachikoma.aseprite` —— 源文件（推荐，便于改）
2. `tachikoma.png` —— **横向一行**精灵表，12 帧按顺序排开（32×12 = **384×32**），padding 全 0
3. `tachikoma.json` —— 元数据

```bash
aseprite -b tachikoma.aseprite \
  --list-tags \
  --sheet tachikoma.png --data tachikoma.json \
  --format json-array \
  --sheet-type horizontal \
  --shape-padding 0 --inner-padding 0 --border-padding 0
```

- `--list-tags` **必须加**：不加，JSON 里就没有 `meta.frameTags`，播放器不知道该播哪几帧。
- `--format json-array`（不是默认的 json-hash）：顺序稳定，按下标取帧。
- `--trim` / `--extrude` / 非 0 padding **必须关**：它们会改帧尺寸和坐标，播放器算帧偏移直接错位。
- **不要**把一个以上的 `.aseprite` 拼进同一张表（会让 tag 帧范围重叠、无法按 tag 取帧）。
- `--split-tags` 不能用来把 sheet+data 拆成"每 tag 一套文件"（实测无效）。不要用它。

**给美术自检用（不是交付格式）**：`aseprite -b tachikoma.aseprite --save-as 'tachikoma-{tag}.gif'`

**播放器读法**：tag 的帧范围 `[from, to]` **含两端**；帧矩形取 `frames[i].frame.{x,y,w,h}`；每帧显示时长由 **T ÷ 取的帧数** 推导（不直接信 JSON 里的 `duration`，只把它当一致性校验）。

## A5. 播放方式与性能约束（工程侧）

**采用：PNG atlas + JSON，CSS `animation` + `background-position`**（对齐仓内 `FileTypeIcon.vue:66-96` 已有的 atlas 取图做法）。

| 方式 | 是否可能走合成器 | 帧时长可控 | 结论 |
|---|---|---|---|
| CSS + `background-position` | ❌ **主线程重绘**（不在 Chromium 108 的可合成属性表里） | ✅ | 首选：零 JS、与仓内做法同构 |
| CSS + `transform: translateY()`（竖条 atlas） | ✅ 有机会（`transform` 在表内） | ✅ | 备选：数量大/掉帧时切换，需 DevTools 确认真的被合成 |
| `<canvas>` + `drawImage` | ❌ 主线程 | ✅ | 兜底 |
| GIF / APNG / animated WebP | — | ❌ **无播放控制 API**（108 没有） | ❌ 做不出同周期不同帧数 |

**性能约束**：

- 同时运行的动画精灵 **≤ 12 个**（超出的节点只对"当前悬停/选中"的动画；确切上限用播放台的 ×12 / ×30 / ×48 压力测试实测后再定，**读数必须在前台真实窗口**，后台会被浏览器节流）。
- **窗口不可见时不保证动画推进**（Electron `backgroundThrottling` 默认 `true`）——这是行为，不是 bug。
- `prefers-reduced-motion: reduce` → **停动画、显示静态第 0 帧**；另加应用内"动画"开关（WCAG 2.2.2 要求应用提供机制）。
- `image-rendering: pixelated` 是唯一可用值（`crisp-edges` 要 Chrome 148，108 无效）；非整数缩放（Windows 125%/150%）会发糊，是**规范行为**，接受。

## A6. 调色板约束

| 项 | 值 |
|---|---|
| 塔奇克马本色 | 美术自定（建议 ≤ 16 色 + 透明），**一套就够，不用为 5 档出 5 套配色** |
| 状态色 | 由工程侧画成节点**色环**（外扩 2px，2px 宽），用 A2 表的 5 个 hex |
| 背景 | 必须透明（不要铺底色） |
| 颜色盲友好 | 不能只靠颜色：色环 + 取几帧（快慢）双重编码 |
| 主题 | 只需在 teahouse **深色主题**下可读；浅色主题不强制 |

## A7. 交付验收清单

1. `tachikoma.json` 里有 `meta.frameTags`，含 `loop`（P1 可选再加 `blink`）。
2. 所有帧尺寸一致（都是 32×32）——不一致 = 开了 trim/padding。
3. 帧数 = 12，横向一行，`tachikoma.png` 宽度 = 384。
4. tag 帧范围不重叠。
5. 把 `tachikoma.png` + `tachikoma.json` 拖进 `docs/design-drafts/stage4/sprite-playground.html`，第 4 区显示 **✓ 合格**。

# B 部分 · 派遣网络图规格

> 由 `docs/design-drafts/stage4/dispatch-network.html` 定案（**默认 variant A = 星系图**，owner 已确认）；截图 `shots/dispatch-network-A.png`。

| 决策点 | 定案 | 为什么 |
|---|---|---|
| 布局 | **星系图（中心-辐条）**：深度 0（常驻成员）在内环 `r=86`，每深一层向外 +88；子节点角度跟随父节点聚集 | owner 明确选 A；#9 也定的"星系式连线" |
| 节点 | **32×32 方形精灵槽**（圆角 4）内画塔奇克马；槽外一圈 **2px 状态色环**（五档 hex）；名字标签在下方 | 精灵就是节点，状态靠色环 |
| 状态编码 | **只靠色环颜色**；节点尺寸**固定**，不编码状态 | 半径编码状态会把"最累"画成"最大"，与"最重要/产出最多"的通用语义相反（variant B 就是这个误读的现场演示） |
| 阈值 | `<10 #3fb950` / `≥10 #d29922` / `≥20 #f0883e` / `≥40 #f85149`；空闲/无数据 = `#58a6ff`；必须同屏记录窗口大小 | 沿用 #9 + owner 口径 |
| 成员类型 | 常驻成员 = 槽位实线描边；派遣成员 = 虚线描边（`3 3`） | 两种身份在成员表里同构，图上必须可辨 |
| 回收 | `#6e7681` + 去饱和 + **虚线描边** + 标注"**退群 HH:MM**"；默认留在原深度位置 | 回收 = 进程已结束，不会再回来 |
| 离线 | **不作为精灵的一档**。teahouse 的 `offlineAfter: 90_000`（presence 静默 90s）只影响成员表头像的底色，与网络图上的精灵无关 | owner 口径："离线？你是说 idle 吗"——他们的模型里没有这一档；两者也不在同一位置出现 |
| 连线 | 贝塞尔或直线 + 末端箭头，常态 `1.6px #3a4256`；与回收节点相连的边 `4 4` 虚线 | 有向（谁派的谁）；回收后不再是活跃路径 |
| 悬停 | 名字 · 成员类型 / 状态名 + `pct%` + 窗口 / 当前任务（会话目标）/ 派遣者 / 派遣深度 / 派遣于；回收额外"退群 HH:MM" | 一屏回答"它是谁、累不累、在干什么、谁派的" |
| 点击 | 高亮该节点到根的**整条派遣链**（链上边 `2.6px #58a6ff`，其余压暗到 32%）；再点取消 | 单条任务的完整路径是演示时的核心叙事 |
| 动画 | 默认不动画；要脉冲只用 CSS `transform: scale()`，**禁止**动 `r` / `background-position` | 只有 `transform`/`opacity` 在 Chromium 108 的可合成属性表里 |
| 数量预算 | 同屏 ≤ 20 节点；20+ 开始有交叉线，30 时靠折叠 | 实测入口在 demo 页压力测试面板 |
