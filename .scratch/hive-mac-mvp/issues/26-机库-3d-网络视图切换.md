## 背景

美术交付了 `docs/prototype/liquid-neural-space-frontend/`（React 19 + three.js 的 3D 语义工作空间原型）。owner 明确定性：**这是机库的另一种视图选择，可以切换**。

## 现有机库架构（已实测）

`vendor/teahouse/src/main/local-api/hangar-page.ts` 是 **local-api 承载的自包含 HTML 页面**（不是 Vue 组件），源码注释说明原因：
- 机库要能被 headless 节点开出来（GUI 与 headless 都挂同一 local-api），而 **headless 不建任何窗口**
- 自包含 HTML + 原生 fetch 让 `GET /v1/hangar` 在两种节点上都可读，CI 也能直接抓它断言
- 由 `hangar-window.ts` 在 GUI 模式下用独立 BrowserWindow 打开

## What to build

在机库页面上增加**视图切换**：默认「原始时间线」（现状），可切到「3D 网络视图」（新）。

## 关键约束与风险

- **体积**：原型 `dist/assets/*.js` 单文件 **1,260,804 B**。**必须**作为独立 chunk 懒加载到机库页；`App.vue` 静态闭包余量已为负，**任何静态 import 都会爆门**
- **依赖树**：React 19 + three 0.180 + r3f + drei + postprocessing + zustand 是**全新一棵依赖树**（vendored teahouse 零 React 零 three）。需评估是否值得，或只取 three（去掉 React 生态）以减小体积
- **Chromium 108（Electron 22）**：WebGL2 可用，three 0.180 基本可跑；`@react-three/postprocessing` 3.x 的后期处理链需真机实测
- **坐标系冲突**：原型 README 红线第 1 条明写「父子层级不能参与坐标计算，坐标只表达工作属性」。而 #57 的 2D 派遣网络图是**深度成环**布局。两者若同屏会打架 —— 本票是机库内视图，与 #57 的主屏网络图**不在同一屏**，但需在文档里写明叙事分工
- **原型占位**：NavRail 三项 `disabled`；Inspector 的 Weight/Traffic 在 Hive 无对应数据 —— **不要**把占位功能直接暴露
- **素材**：原型 `public/tachikoma.png` 与 `docs/UI-draft/233efe81...png` md5 相同；`public/audio/*.mp3`（22KB，来自第三方站点）非核心，可删
- **资产入库**：`docs/prototype/` 目前**未入 git**。建议只入 `src/` + `public/`，**不入 `dist/`**（构建产物）

## 环境约束
