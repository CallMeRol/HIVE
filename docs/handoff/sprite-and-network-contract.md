# A 部分 · 状态精灵（交付美术）

## A0. 一句话

**五只塔奇克马（一套线稿、五套配色），每只 6 帧循环；档位由配色 + 循环节拍表达，不由色环表达。**

状态色**就是塔奇克马自己的配色**——美术已交付的五个 GIF 各是一个档位，配色与 A2 的五档 hex 一致。因此节点上**不再另画色环**（配色已经承担了色相编码），也不再对同一只精灵按档位取不同帧数的子集。

## A1. 画布、缩放与交付实况

已交付精灵资源的实测基线（资源将在 #57 的产品资产目录落位）：

| 项 | 实测值 |
|---|---|
| 画布 | **128×128**，6 帧，背景透明 |
| 帧几何 | `dispose=Background`，帧位移不同（如 `sleep` 首帧 `128×128+0+0`、其余 `≈108×110+13+3`） |
| 原生细节 | **128px 原生**（非整数倍放大的像素画）——缩到 32px 会不可读，见下 |
| 循环周期 | `ease` **1.0s** · `sleep`/`tired`/`super_tired` **1.5s** · `ran_out` **2.0s**（帧延时 17/25/33cs） |

| 项 | 值 | 为什么 |
|---|---|---|
| 原生槽位 | **最小 64×64**：仪表盘卡片、成员详情、派遣网络图节点槽都用 64；128 = 1× 用于单成员大图 | 128px 原生细节缩到 <64 只剩轮廓（实测见下） |
| 缩放 | 只允许**整数比或 0.5× 半比**：64 = 0.5× · 128 = 1× | 0.5× 是 128 的整数分之一，D PR 下最稳 |
| `image-rendering` | `auto`（**不用** `pixelated`） | 资源已是原生细节，`pixelated` 只会在非整数比下制造锯齿 |
| 出现在哪 | **派遣网络图节点槽**（64）+ **仪表盘卡片 / 成员详情**（64）+ **机库卡片**（64）+ **单成员大图**（128） | 消息流和成员表空间紧凑，统一使用名字头像 + 五档状态点 |
| 消息流与成员表头像位 | **不放精灵**：使用名字头像，右下角显示五档状态点 | 与 Spec #41 的 UI 口径一致 |
| **禁止** | 非整数比缩放（如 128 → 32、1.5× 等） | 必然插值发糊 |

**分辨率下限（实测，非保守）**：`sleep.gif` 分别缩到 **32 / 48 / 64 / 128** 比对——**64 起**才保留"红眼 + 银爪"这些识别特征，48 已模糊，32 只剩一团蓝。故**槽位最小 64**；若某处布局只放得下 32，该处不画精灵（改名字首字母头像 + 五档配色小圆点），而不是硬缩。

## A2. 状态 → 动画映射表

五档配色（固定 hex，**由该档 GIF 的塔奇克马配色承担**，不另画）。**轴名 = 上下文负担（Burden）**（#26 定案）：窗口越满，负担越高，表现越不稳；下表五个档名即**负担档**：

| 档位（负担档） | tag | 判据（上下文负担 = 窗口占用 `used / size`） | 配色 hex | 资源 | 一个循环周期 |
|---|---|---|---|---|---|
| **空闲** | `idle` | 没有在跑的会话 **或 拿不到负担数据** | 蓝 `#58a6ff` | `state/sleep.gif` | **1.5s** |
| **轻松** | `easy` | `< 10%` | 绿 `#3fb950` | `state/ease.gif` | **1.0s** |
| **有点忙** | `busy` | `≥ 10%` | 黄 `#d29922` | `state/tired.gif` | **1.5s** |
| **过载** | `overload` | `≥ 20%` | 橙 `#f0883e` | `state/super_tired.gif` | **1.5s** |
| **快炸了** | `about-to-blow` | `≥ 40%` | 红 `#f85149` | `state/ran_out.gif` | **2.0s** |

- **色相是主编码，节拍是副编码**：负担越高整体越慢（1.0 → 1.5 → 2.0s），配色从绿到红。颜色盲也能靠节拍区分。
- **不再另画节点色环**：塔奇克马自身的配色就是档位色（A0）。旧口径的「环 + 取几帧」作废。
- **不按档位切帧数子集**：资源是五只独立的 6 帧循环，各播各的整段；不做"从 12 帧里取 6/9/12"。
- **阈值可调**，默认 `10 / 20 / 40`。
- **必须同时记录窗口大小**（`size`，1M 是主流默认）：同为 10%，200K 窗口和 1M 窗口是完全不同的处境。UI 上要显示窗口。
- **拿不到负担数据 → 按 `idle` 蓝渲染并继续循环**（owner 口径：“没停顿”）。不引入“未知档”，不出现静止态。
- **跨机行（#38 定案）**：配色**只对「本该上报的」对端**判定 —— 即**与本机有共同群、且声明了 `ag1`** 的节点。这个集合里的对端拿不到数据（这一拍没到）仍落 `idle` 蓝（#26「没停顿」）。
- **结构性无状态的对端不用负担配色**（#38 定案）：不在同群 / 未声明 `ag1` / 旧版本 —— 保留底座绿/灰点，**不**落 `idle` 蓝。「永远不会有」≠「空闲」。
- **跨机状态的来源**：hive 私有 `agent-status` best-effort 单播（节拍 `10s`、无数据 TTL `3× 节拍 = 30s`、只对同群 `ag1` 在线节点）。参数与 payload 定稿见 [#38](https://github.com/toRolex/hive/issues/38) resolution；**离线（90s）不参与判定**（#26）。
- **成员离线（够不着）不换配色**：仍按负担档渲染，拿不到数据时落 `idle` 蓝。可达性由底座成员表的置灰承担（#26 定案）。
- **只做循环小动**（呼吸；眨眼可作为循环内的一小段），不做状态切换的一次性动画（#9 已定）。现有 5 个 GIF 都已是循环。
- 不按档位改姿态——现有资源每档姿态已由美术画死在各自 GIF 里，播放器不再改姿态。

## A3. 循环方式与节拍

**实况**：五档是五个独立 GIF，各自 6 帧、**周期不同**（`ease` 1.0s / `sleep`·`tired`·`super_tired` 1.5s / `ran_out` 2.0s）。这与旧口径"共用同周期 T、按档取 6/9/12 帧"相反——**周期差本身就是负担的副编码，保留它，不做相位对齐**。

| 项 | 值 |
|---|---|
| 每档帧数 | **6 帧**（固定，不按档变） |
| 各档周期 | 见 A2 表；**故意不同**，负担越高越慢 |
| 帧延时 | 直接采用 GIF 自带的 `delay`（17 / 25 / 33 cs），不重算 |
| 循环 | 现有 5 个 GIF 已无缝循环；不再要求美术另出母版 |
| 可选（P1） | 若美术愿意，统一调成同一周期 T，回到"相位对齐"口径（旧方案，本次不强制） |

**帧率由资源自带，不由我们的数据推导。**

## A4. 交付格式与命名

**已交付（本次以此为准，不另出格式）**：

#57 应将以下五个 GIF 放入统一的产品资产目录；文件名与语义冻结如下：

| 文件 | 档位 | 周期 |
|---|---|---|
| `sleep.gif` | `idle` 空闲 | 1.5s |
| `ease.gif` | `easy` 轻松 | 1.0s |
| `tired.gif` | `busy` 有点忙 | 1.5s |
| `super_tired.gif` | `overload` 过载 | 1.5s |
| `ran_out.gif` | `about-to-blow` 快炸了 | 2.0s |

规格：`128×128` 画布 / 6 帧 / 透明背景 / `dispose=Background`。文件名沿用美术原名，不重命名。

**改图时必须重跑导出**（若日后需要重导出或改帧）：

```bash
magick -dispose Background -delay 17 -loop 0 frame*.png out.gif
```

- `dispose=Background` **必须显式给**：缺了它上一帧会残留在下一帧下面（现有资源就是靠它清帧）。
- `-delay` 按档位给 `17 / 25 / 33`（cs），不要统一。
- 帧尺寸**不要** trim 到内容边界后不记位移：现有 GIF 各帧 `+X+Y` 位移不同，播放器按画布对齐即可，不要按帧尺寸重算。

**播放器读法**：GIF 自带时序，直接用 `<img src>` 或 `background-image` 播放即可（GIF 不可暂停/不可换帧，见 A5）；若要自绘循环，按 A1 的原生槽位尺寸渲染，保持 `image-rendering: auto`。

## A5. 播放方式与性能约束（工程侧）

**采用：GIF + `<img>` / CSS `background-image`**（与现有资源一致，零 JS、零 atlas 解析）。旧口径的 "PNG atlas + JSON + CSS `background-position`" 作废。

| 方式 | 是否可能走合成器 | 帧时长可控 | 结论 |
|---|---|---|---|
| GIF `<img>` / CSS 背景 | ✅ 解码在图片线程，主线程不重绘 | ❌ **无播放控制 API**（Chromium 108） | **采用**：资源已是 GIF，直接播 |
| CSS + `background-position` atlas | ❌ 主线程重绘 | ✅ | 仅在日后改出 atlas 时启用 |
| `<canvas>` + `drawImage` | ❌ 主线程 | ✅ | 兜底 |

**性能约束**：

- 同时运行的动画精灵 **≤ 12 个**（超出的节点只对"当前悬停/选中"的动画；确切上限由 #57 在前台真实窗口以 ×12 / ×30 / ×48 压力档实测后再定，后台读数会被浏览器节流）。
- **窗口不可见时不保证动画推进**（Electron `backgroundThrottling` 默认 `true`）——这是行为，不是 bug。
- `prefers-reduced-motion: reduce` → 只显示 GIF 首帧（静态，用 A1 的整数比尺寸）；另加应用内"动画"开关（WCAG 2.2.2 要求应用提供机制）。
- `image-rendering: auto`（资源是原生细节，不用 `pixelated`）；非整数比缩放（Windows 125%/150%）会发糊，是**规范行为**，接受。

## A7. 交付验收清单

1. 五个 GIF 都在，文件名与 A4 表一致。
2. 每个都是 `128×128` / **6 帧** / 透明背景 / `dispose=Background`。

# B 部分 · 派遣网络图规格

> 采用已确认的 variant A 星系图方向；下表是现行实现规格，历史原型不得覆盖它。

| 决策点 | 定案 | 为什么 |
|---|---|---|
| 布局 | **星系图（中心-辐条）**：常驻成员为派遣深度 1，位于环序号 0 的内环 `r=86`；派遣深度每加 1 向外 +88；子节点角度跟随父节点聚集 | owner 明确选 A；#9 也定的"星系式连线" |
| 节点 | **方形精灵槽**（圆角 4）内放该档 GIF：**64×64**（128px 原生细节的可读下限，见 A1）；**不另画色环**；名字标签在下方 | 精灵就是节点，状态靠配色 |
| 状态编码 | **靠塔奇克马自身配色 + 循环周期**（A2）；节点尺寸**固定**，不编码状态 | 半径编码状态会把"最累"画成"最大"，与"最重要/产出最多"的通用语义相反（variant B 就是这个误读的现场演示） |
| 阈值 | `<10 #3fb950` / `≥10 #d29922` / `≥20 #f0883e` / `≥40 #f85149`；空闲/无数据 = `#58a6ff`；必须同屏记录窗口大小 | 沿用 #9 + owner 口径 |
| 成员类型 | 常驻成员 = 槽位实线描边；派遣成员 = 虚线描边（`3 3`） | 两种身份在成员表里同构，图上必须可辨 |
| 回收 | 成员从成员表与派遣网络图**立即硬删除**；不置灰、不留幽灵、不显示退群时间 | 图只表达活跃协作关系；历史查群消息流 |
| 离线 | **不作为精灵的一档，也不改配色**：够不着时仍按负担档配色，拿不到数据落 `空闲` 蓝；离线是底座 presence 事实（静默 90s），网络图上不另加视觉 | owner 口径：“离线？你是说 idle 吗”；#26 定案：够不着的成员可能正跑得好好的，不猜、不占档 |
| 连线 | 贝塞尔或直线 + 末端箭头，常态 `1.6px #3a4256`。**父退群后子的边重挂最近活跃祖先（无祖先挂群中心），边两端恒为活跃节点**（#31 孤儿链 = 跳级挂靠） | 有向（谁派的谁）；图不引用已消失者 |
| 悬停 | 名字 · 成员类型 / 状态名 + `pct%` + 窗口 / 当前任务（会话目标）/ **派遣者 = 当前活跃挂靠父（无则主人）** / 派遣深度（活跃链上代数）/ 派遣于 | 一屏回答"它是谁、累不累、在干什么、谁派的"；只陈述当前事实（#31） |
| 点击 | 高亮该节点到根的**整条活跃派遣链**（链上边 `2.6px #58a6ff`，其余压暗到 32%；孤儿沿跳级挂靠后的边走，根 = 常驻成员或群中心）；再点取消 | 单条任务的完整路径是演示时的核心叙事（#31） |
| 动画 | **就用 GIF 自带循环**（A5）；要额外脉冲只用 CSS `transform: scale()`，**禁止**动 `r` / `background-position` | 只有 `transform`/`opacity` 在 Chromium 108 的可合成属性表里 |
| 数量预算 | **无独立同屏预算**：节点数由派遣深度上限 × 并发上限导出（默认 3 × 5 → 峰值 31，均可配），**画全部活跃成员**；不折叠 / 不过滤 / 不分层；名字标签恒显，压叠交给布局、实现时再定 | #31 定案（owner）：原「同屏 ≤ 20」与原型页「≤12 标签压叠」均为 AI 合成、未经审核 → 作废 |

## #26 定案（本文件的修订来源）

- **轴名**：`上下文负担`（Burden）——窗口越满，负担越高，表现越不稳（越压越糊）。
- **五档改名**：`空闲 / 轻松 / 有点忙 / 过载 / 快炸了`（tag `idle / easy / busy / overload / about-to-blow`）；hex 与 `10 / 20 / 40` 阈值不变。
