# 交接文档填写规则

模板骨架唯一来源：`TEMPLATE.md`。运行时若需内嵌模板，引用该文件，不另写一份。
契约 = **Markdown H2 节名**，不是 JSON schema（原三张 schema 已砍，不复活）。

必填 = 头部元数据 + 7 个 H2 节：`当前目标` / `已完成` / `关键决策` / `产物引用` / `未决问题` / `下一步` / `suggested skills`。

## 1. 已完成防幻觉

- 每条「已完成」必须带**产物引用三件套**：路径 + 哈希（**sha256 定死**）+ 可复跑命令。
- 没有产物的条目不得写「已完成」；没做的事不许写。

## 2. 引用不复制

- 不重复 spec / plan / ADR / issue / commit / diff 等其他 artifact 已有内容，只写路径或 URL。
- `产物引用` 节是集中索引；条目内嵌引用与索引不一致时**以内嵌为准**。

## 3. 脱敏

- API key、密码、个人身份信息一律不落盘。

## 4. 落盘位置

- 派遣者机器的产物目录：`<artifactsRoot>/handoffs/<sessionId>-<YYYYMMDD-HHmmss>.md`。
- `artifactsRoot` 根路径实现期按 teahouse 用户数据目录定，允许环境变量覆盖。
- **绝不传会话历史**。

## 5. 跨机引用

- 路径一律使用绝对路径并带机器前缀 `<machine>:`（机器 = 成员表里的节点名）；同机也不得省略。

## 6. 派遣事件的最小字段（群可见消息）

```
{ 派遣者, 成员（可多个）, 会话目标一句话, 派遣深度 d（上限 N 来自配置）}
```

- 恰好 4 个字段；渲染沿用 teahouse 消息格式，形如：`A 把 B 拉进群：<目标一句话>（深度 d/N）`。
- **不含**：产物引用、角色标签、交接文档内容、任何会话历史。产物引用只存在于交接文档。

## 7. 角色标签

- **由谁写**：目标抽取器在会话目标定稿时**自动派生**，不设独立人工输入；守卫单次越界产出的派单草案走同一抽取器。改目标即改角色，不单独确认。
- **写在哪**：会话元数据（成员 session record），UI 显示在成员名旁；交接文档头部元数据复述一份。
- **不进派遣事件**（进事件即双写、必然漂移）；群内需要展示时由前端从目标派生。

## 8. 不硬编码（扩展规则）

- 读取方按节名查找：缺节容忍、**未知节原样保留并忽略**。
- 新增字段 = 新增 H2 节或头部元数据行；新读旧、旧读新都只缺内容、不报错、不丢数据。

## 9. 已知风险

- **跨机交接文档投递通道未定**：MVP 兜底——同机直读路径，跨机随派遣的私有载荷投递（不进群可见消息）。
- `artifactsRoot` 根路径依赖 teahouse 存储布局，实现期定。
- 样例数据全虚构，防被误读为真实凭据。
