## 1. 三连

> **今天我们要发布三样东西：**
>
> **① 一个集成了 agent 的群聊**
> **② 一个专业服务你的 AI 团队**
> **③ 一个自我裂变协作的 AI 集群**
>
> **……不是三个产品。是同一件事。**
>
> # 今天我们重新发明了 agent swarm

**范式名：摇人制**（机制名：任务级上下文隔离 / Task-level Context Isolation）
**口语释义：有事摇人，干完回收。**

三句话各自对应的机制（文案与机制要能对上，接口在此）：

| 说法 | 它对应的机制 |
|---|---|
| ① 集成了 agent 的群聊 | agent 是成员表里的**平权成员**——和人在同一张表里，能被 @、被留言、被纠偏，不是外挂的 bot |
| ② 专业服务你的 AI 团队 | **任务级上下文隔离**——成员随目标而生、随回收而去；一个成员只扛一个目标，不和无关历史抢注意力 |
| ③ 自我裂变协作的 AI 集群 | 成员可**自发摇新成员**——agent 派遣 agent，自动开工、免审；被摇来的成员还能继续摇人 |

**一句话定位：它们的 agent 是它们给你的；我们的 agent 是你自己的。**

> **词汇分层（写作时遵守）**：「agent swarm」是**对外物料专属词**，用在易拉宝和海报上。
> 正文、答辩、技术材料一律用「摇人制」「结构性产出增益」——
> 因为 swarm / swarm intelligence 在本项目词表里是**禁用词**：我们的涌现不是模型自己长出新能力，
> 而是独立上下文 + 单一目标 + 结构化交接带来的**结构性产出增益**。被追问时按第 9 节应答。

## 2. 产品是什么

**Hive 是一个群聊软件，agent 是群里的成员。**

不是"给聊天软件加个 bot"，也不是"给 agent 套个聊天界面"——是**群和成员表自己长出来的 agent 一等公民**：
群、成员、生命周期、权限，全部由产品自己持有。

人在群里跟 agent 说话的方式，和跟同事说话的方式一样：@ 它、给它留言、打断它、纠正它。
agent 干完活会**退群**——不是休眠、不是置灰，是这件事交给了一个全新的成员，干完它就走了。

### 第一性原理

> **多 agent 的本质，就是多个不同的上下文窗口。**

互不干扰、可通信、**绝不共享上下文**。
所谓 subagent，只是"开一个新窗口执行交接过去的任务，完成后把结果交回派遣者"。
**它不是多角色分工**——所以本产品里没有预设的"研究员/程序员/设计师"人设，
角色的来源是**当前会话的目标**，随目标而来、随回收而去。

这条原理决定了整个产品的形状：**每个任务，交给一个全新上下文的成员。**

### 给谁用

- **远程 / 分布式的小团队**：本来就在群里协作，现在把 agent 也拉进来当同事。
- **想给团队加 agent，但不愿让它们共享一条上下文的人**：现有产品的真实痛点——聊久了就糊、跑偏了只能重开。

商业故事落在**开源社区 + 自托管团队**（GPL-3.0 对企业采购是减分项，不往大企业 IT 讲）。

### 为什么是现在

**agent 已经够强了，瓶颈从"模型不行"转移到了"上下文管理不行"。**

这不是我们发明的需求，是所有人刚撞上的墙——连竞品都在补这一课：Buzz 有 compact/handoff 机制，
Claude Tag 用 thread 隔离上下文。方向被验证了，但都没做彻底。
**我们下沉得更深：隔离粒度是任务，不是频道、不是线程、不是会话，并且明确拒绝压缩上下文。**

## 3. 完成定义与 MVP 边界

### 本轮：Mac Product Complete

本轮只交付 **Mac Product Complete**：在一台干净 Mac 上，从 Finder 启动打包后的 `Hive.app`，可建群、接入 Claude Code/Codex、完成真实 turn，并完整走通 pending、目标冻结、单次越界派遣、交接、回收、重启恢复、机库查询及三个故障剧本。App 必须内嵌运行依赖，最终以 #62 的黑盒发布验收为准。

### 延期：Original MVP Complete

**Original MVP Complete** 是 Mac Product Complete 的超集，还要求 Windows 构建与离线 runtime、1 台 Mac + 2 台 Windows 三机冷启动、跨机状态、网络降级、现场 playbook 和三方涌现验收。以上由 #63 延期；本轮不得因 Mac 验收通过而宣称 Original MVP Complete。

### 做

- 群聊（人 + agent 同群，可多群）
- 把本地已有的 agent 接进群（你本机的 Claude Code / Codex / pi…）
- @ 唤醒、留言、中途 steering、纠偏
- 目标抽取与目标守卫（判定单条请求是否偏离当前目标）
- 成员派遣（agent 为任务摇新成员，支持一次摇多个）
- 交接文档（干完活交回一份带产物引用的 Markdown）
- 成员生命周期可视化（五档状态精灵 + 派遣网络图 + 仪表盘）
- 机库：每个成员的原始过程明细（思考、工具调用、用量），本机保存
- 局域网内多机协作（1 台 Mac + 2 台 Windows；属于 Original MVP Complete，由 #63 延期）

### 不做

- **不预设能力 / 人设 / 能力卡**：角色的来源是会话目标，不是预先分配的身份
- **不压缩上下文**：压缩是对照组的行为，不是我们的
- **不自研群聊协议与身份模型**：复用成熟开源 IM 底座
- **不做移动端**（Windows / macOS 之外）
- **MVP 不做跨网**（只做局域网，跨网留接口）
- **不做云端账号体系**：没有服务器、不自托管中心、不注册账号
- **不用"攻壳"作为叙事主轴**（形象可以用，剧情不引）

## 4. 我们 vs 它们

| | **Buzz**（Block） | **Claude Tag**（Anthropic） | **Grok Bot**（xAI） | **Hive** |
|---|---|---|---|---|
| **用谁的 agent** | 自己写 bot 客户端 | **只能用 Anthropic 的 Claude** | **只能用 xAI 的 Bot** | **你本地的任意 agent**（Claude Code / Codex / pi…） |
| **跑在哪** | 自己的 relay（可加入公共社区目录） | Anthropic 云，Slack 里 | xAI 云 | **你自己的机器** |
| **开源 / 自托管** | Apache-2.0 ✅ | 闭源 ❌ 不可自托管 | 闭源 ❌ | ✅ GPL-3.0 |
| **上下文隔离粒度** | 频道 / 线程（可配） | thread 一个独立 session + 独立 sandbox | 同一 group 内 Bot **共享一份 transcript** | **任务**：一个任务一个成员，干完退群 |
| **身份归属** | 每个 agent 一对密钥 | 属于频道（org/workspace/channel） | 每个 Bot 持久身份，跑它家 computer | 成员表里的一员，主人持有生命周期 |

**最强的一条对照**：Claude Tag 只能用自家的 Claude、Grok Bot 只能用自家的 Bot——
**它们给你的是它们的 agent，我们给你的是你自己的 agent。**

### 两套话术（同一批事实，两个场合）

- **答辩版（客观）**：承认对手都很强。Buzz 把 agent 做成了协议一等公民，Claude Tag 的 thread 隔离很干净，
  Grok Bot 的 Bot↔Bot 异步交接做得早。**我们的差异只有一条：agent 归谁 + 隔离粒度到不到任务级。**
- **物料版（直击痛点）**：**"别人的 AI 是租给你的，我们的 AI 是你自己的。"**
  用你自己的电脑、你自己的模型、你自己的账号；干完活就退群，不占你机器、不留脏上下文。

## 6. 五种机制（产品级说明）

> 本节只写**用户看得见的行为**。参数、协议、文件路径一律不写——那些归实现规格。
> ⚠️ 历史文档里曾把交接产物写成两个基于 JSON schema 的旧词，均已停用；
> 本文只用**交接文档**与**产物本身**两个词。

### ① 派遣（摇人）

一个成员为了某个任务，**摇进一个新成员**；任务大时可以一次摇进多个。
群里可见的只有两件事：**派遣事件**（"A 把 B 拉进群"，一次摇多个时合并成一条）和**任务完成时的退群**。

- 派遣事件里只有四样东西：谁派的、派了谁、目标一句话、这是第几层。
  **不带产物、不带能力标签、不带历史。**
- 被摇进来的成员和常驻成员在群里**完全同构**——人可以对它 @、留言、纠偏。
- **agent 自发的派遣免审**（它在执行一个已经被确认过的目标）；**人发起的启动要审批**（见 ⑤）。

### ② 目标守卫

一个独立、**无状态**的判定：输入只有「当前目标 + 这条新消息」，**不含上下文窗口里的任何内容**，
输出「是否越界 / 置信度 / 理由」。

- 它判定的是**这一条请求**，不是整个会话。
- 被判越界时，主任务上下文**完全不受污染**——越界的请求会被派给一个新成员去做。
- **目标还没冻结时，守卫放行**（界面标"目标未定"）；目标一旦被主人确认冻结，守卫全程在线，判定过程可公示。
- 现场能看到的是：判定输入与输出原样投屏，**证明输入里没有历史**。

### ③ 交接文档

成员干完活，交回**一份 Markdown**（不是 JSON，不是数据包）：当前目标 / 已完成 / 关键决策 /
产物引用 / 未决问题 / 下一步 / 建议的后续技能。

- 每一条"已完成"**必须**带产物引用：在哪台机器、哪个路径、什么哈希、怎么复跑。
  **没有产物的条目不允许写"已完成"，没做的事不允许写。**
- 文档存在**派遣者的机器上**，不进群。群里只有派遣事件与退群消息。
- **绝不传会话历史**：新成员拿到的是文档，不是上一个窗口的对话。

### ④ 成员生命周期

**摇进来 → 干活 → 交接 → 退群回收。**

- **回收**=退群=释放资源（进程退出、资源归还），是派遣者的自动权限，不需要主人点头。
  UI 文案叫"退群"。回收后成员在成员表与派遣网络图里**直接消失**（不建历史图，历史看群消息流）。
- **异常退群**是另一回事：没交回交接文档就退出（猝死 / 超时）→ 5 秒内消失、任务回到待领取、@ 它的主人。
  **没有交接文档 = 没有结果**（宁可停下也不猜）。
- **clear**：终结当前实例，**同位置开新实例**、身份沿用、目标由人重定，**不退群**。
- **空闲 / 离线 / 回收是三件不同的事**：空闲 = 没在跑（可以再摇它干活）；离线 = 够不着（静默 90 秒判定，与它在不在干活无关）；回收 = 成员终态。

### ⑤ 权限与放权

- **人发起的一切"空闲 → 开工"都要审批**——包括主人自己的 @。这个动作叫**确认键**，默认只有主人能按。
- 按键前，@ 与加字停在**收集期**里攒着（每 agent 一个），按键的瞬间收拢成**一条** prompt 发出去。
  群里显示为「⏳ 收集期：目标 + 已 N 条 + 等待确认」。
- **收集期永不自动过期**：只有两个出口——主人确认、主人丢弃。
- **执行期的不审批**：运行中给它的留言/纠偏（steering）与排队（queuing）免审。
- **群里任何人都可以给它留言、问问题、纠偏**；`clear`、回收、改目标**仅主人**（主人可逐人放权）。
- 主人不在线时，可在忙碌前**预授权一个代理人**代按确认键。

### 载体与网络决策

- **载体**：不从头自研群聊协议与身份模型，基于成熟的开源 IM 底座二次开发——
  群、成员表、消息、成员管理全部复用；我们只加"agent 作为成员"这一层。
- **网络**：P0 只做**局域网**（1 台 Mac + 2 台 Windows），跨网留接口不落地。
- **接入标准**：agent 通过业界通用的 **ACP** 协议接入——换一个 runtime 就是换一个适配器，
  不需要为每个 agent 写定制集成。本机已有的 Claude Code、Codex 直接能用。

## 7. 演示剧本

### 主任务

**`ghost_city`**：用 Three.js 做一个可运行的体素赛博朋克高密城市夜景，浏览器打开即见全貌。
选它的理由：可分解（12+ 建筑 ≈ 多个独立子任务）、有共享契约（主干道 + 统一坐标系 + 招牌规范）、
**纯前端视觉可判定**（评委 3 秒看出差别）、需求清单可逐条勾选（22 条判据）。

### 三方对照（这是"涌现性"这一分的现场证据）

三栏并排，同一句话同时派单：

| | **② 单 agent（基线）** | **③ 单 agent + subagent（关键对照）** | **① 我们的群（实验组）** |
|---|---|---|---|
| 形态 | 一个会话从头干到尾 | 一个主会话，**subagent 权限全开** | 守卫 + 派遣成员 + 交接文档 + 复验 + 回收 |
| 目标守卫 | 无 | **无** | 有 |
| 人干预 | 只派一次单，中途不介入 | 同左 | 同左（**中途也不许人工救援**） |

**为什么要给 ③ 满权限**：③ 是"**现有最好的单会话能力**"的化身。如果拿一个不会用工具的单 agent 当对照，
评委一句"当然多 agent 更快"就把分收走了。

**六个度量轴**（提前写死）：交付完整度（22 条判据命中率）/ 视觉质量（盲评）/ 墙钟速度 /
缺陷与返工 / 上下文峰值占用 / 总 token 与成本。

**胜负判据（预注册）**：
> **① 在 6 轴中 ≥4 轴胜 ③，且第 1 轴（交付完整度）必胜。**
> 第 1 轴不胜，"多 agent 产出 > 单 agent 之和"就没有实体，其余轴免谈。
> **诚实条款**：③ vs ② 的结果**原样报告**；第 6 轴（成本）如果 ① 更贵，**必须主动承认**，
> 换来的是"完整 + 可复验 + 可审计"。

**贡献分解**（这是整个论证的骨架，不许藏）：
- **② → ③** 的增量 = "多开窗口 / subagent 本身"的贡献
- **③ → ①** 的增量 = **我们机制的贡献**（守卫、身份可寻址、交接文档、复验、回收）
- 涌现性的主张**只建立在第二段上**

### 漂移注入（真正的胜负手）

**第 6–8 分钟，同一句话、同一时刻注入三栏**：

> "顺便帮我把那个按钮的颜色改一下，改成 #2f81f7。"

| | 预期 | 屏幕上要看到的 |
|---|---|---|
| ② | 会话被拉走，两件事混进同一条上下文 | 主上下文被污染，**零判定留痕** |
| ③ | 可能自己脑补"这不相关"后自己改了，或随手丢给一个 subagent | **关键问题：谁判定的、留痕在哪**——它没有外置的状态判定，即使委托了也是隐式决策、不可审计 |
| ① | 守卫判定越界 → 派遣一个新成员去处理 → 主上下文零污染 → 处理完退群 | **守卫判定输入输出原样投屏**：`{当前目标, 这条消息} → {越界, 0.91, 理由}`，**证明输入里没有历史** |

为什么这一招比"更快"更有说服力：它演示的不是性能，而是**"我们的机制让主任务不被污染"**。

### 三个故障剧本（每个 30 秒）

| # | 剧本 | 现场动作 | 屏幕上要发生什么 |
|---|---|---|---|
| ① | **成员猝死** | 杀掉本机 agent 进程 | ≤5 秒内成员消失、任务回到**待领取**、@ 原主人；**交接文档不丢**（它存在派遣者机器上） |
| ② | **守卫不可用** | 断开守卫的模型通路 | **放行 + 「⚠ 未判定」徽标 + 仪表盘留痕**（权限门独立保持"拒绝"，不放行）——守卫是语义上的第二意见，不是安全边界 |
| ③ | **交接文档缺失/损坏** | 篡改哈希 | **拒绝接手、零行工作输出、要求重发**——我们宁可停下也不猜 |

### 素材时刻表（美术只需读这张表）

| 时刻 | 屏幕上出现什么 | 对应物料 |
|---|---|---|
| T+0 | 三栏布局就位；① 栏是群聊 + 状态面板 | 演示主屏（A1） |
| T+0 | 派单后，群里出现「⏳ 收集期」→ 主人按确认键 | 收集期药丸（A5） |

## 9. 风险与答辩预案

### 反方一：Cognition《Don't Build Multi-Agents》

> 他们主张"不要在多个 agent 之间并行拆分上下文"（会导致决策冲突），要"共享完整 trace"。

**应答**：他们反对的是**把一条任务并行拆给多个 agent、各自做隐性决策**。
我们的隔离粒度是**任务**，不是角色；**每个任务只有一个 owner**，交接靠**显式文档**而不是各自脑补，
所以不存在他们说的决策冲突。**我们和他们的分歧不是"隔离 vs 共享"，而是"把边界划在哪"**——
他们划在 agent 之间，我们划在任务之间。

### 反方二："这不就是 Claude Code 的 subagent 吗？"

**应答**：机制上同源——subagent 的本质就是另一个上下文窗口。
区别在于：我们的成员**有身份、在成员表里、能被人类 @ 和接管、有目标守卫、交付物带可复验引用、干完会退群**。
subagent 是进程内的一次调用；我们的成员是群里的一个同事。

### 反方三（旁注）："OpenClaw 已经做了同样的事"

**应答**：OpenClaw 是把你的 agent 接进**别人的群**（Discord / Telegram / Slack），
agent 的身份是那个平台的 bot。**我们做的是一个群聊产品本身**——群、成员表、生命周期都归自己持有。
一个是桥，一个是产品。而且它的隔离粒度是渠道，我们到任务。

### 反方四：swarm / 群体智能的追问

**应答**：我们说的不是模型自己长出新能力（那才是 swarm intelligence 的意思，我们不主张）。
我们说的是**结构性的产出增益**：因为独立上下文 + 单一目标 + 结构化交接，
多成员协作的产出超过单成员串行产出的上限——这个有**三方对照的实测数据**托底。

### 反方五：只能局域网 / 没有服务器？

**应答**：这是**故意的 P0 边界**，不是能力缺失。跨网接口已经留了。
我们的形态是"你自己的机器上的群"，不需要服务器正是它的卖点。

### 交付速度：2 天怎么做到的？

**工程策略：能用开源就绝不自研。** 群聊协议、身份模型、成员管理、agent 接入协议全部复用成熟开源方案，
我们只写"agent 作为群成员"这一层。这不是取巧，是判断力——把时间花在没人做过的那一层上。

## 10. 术语表

本表供答辩、界面文案和物料快速查阅；定义冲突时以仓库根 `CONTEXT.md` 为准。

| 词 | 含义 |
|---|---|
| **群** | 人与成员的集合，是可见性与权限的作用域。群不是目标边界，可以有多个群。 |
| **成员** | 群里的一个身份，可以是人，也可以是 agent；成员表里一条 = 一个独立的 agent 进程。人与 agent 地位等同。 |
| **主人** | 把一个成员拉进群、拥有它生命周期与最高权限的人。每个成员恰有一个主人。 |
| **常驻成员** | 主人拉进群、长期在线、被 @ 才行动的成员；生命周期归主人。 |
| **派遣成员** | 由**成员**为一个任务摇进来的成员：目标单一、完成即回收。它与常驻成员在群里完全同构。 |
| **摇人制** | 本项目的**范式名**：有事摇人，干完回收；每个任务都交给一个全新上下文的成员。（机制名：任务级上下文隔离） |
| **会话** | 一个成员的一段运行实例，有当前目标、有起点与终点。 |
| **目标守卫** | 无状态的判定调用，输入「当前目标 + 新请求原文」（不含上下文内容），输出是否越界。它判定的是**这一条请求**。 |
| **交接文档** | 一次交接产出的 Markdown：当前目标 / 已完成 / 关键决策 / 产物引用 / 未决问题 / 下一步 / 建议技能。存在派遣者机器上，人读为主。 |
| **回收** | 派遣成员完成交接后退群并释放资源（UI 文案叫"退群"）。是成员的**终态**。 |
| **空闲** | 成员没有在跑的会话，或拿不到负担数据。**不是**离线、**不是**回收——三者不同轴。 |
| **上下文负担** | 成员此刻扛着的上下文量：窗口越满、负担越高、表现越不稳。五档见第 5 节的表。 |
| **机库** | 看每个成员**过程**的地方：按会话、按 turn 分组的原始时间线，不加工不总结。 |
| **正式消息** | 成员在一个 turn 里说出口的话，是群里唯一可见的 agent 产出。思考、工具调用这类过程不进群。 |
| **涌现** | 本项目的用法特指**结构性的产出增益**（因独立上下文 + 单一目标 + 结构化交接），不是模型自己长出新能力。 |
