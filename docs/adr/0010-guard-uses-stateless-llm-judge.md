# 目标守卫用无状态 LLM 判定（Plan A），不用规则层与判别式模型

目标守卫需要判定「新请求是否偏离会话主目标」，我们决定采用 Plan A：一次独立、无状态的 LLM 判定调用，输入仅 `{当前目标, 新请求原文}`，不带任何会话历史；不设规则短路层；Plan B 判别式模型仅作降本备选。产品层「零污染、投屏可证」的 why 见 `docs/PRD.md` §6② 与 §7（漂移注入），此处不复读。

## Status

accepted

## Decision

- **判定形态**：独立的、无状态的 LLM 调用，可与干活 agent 使用不同、更便宜更快的模型。
- **输入**：仅 `{当前目标, 新请求原文}`——**不含会话历史、不含上下文窗口任何内容**。
- **输出**：结构化 `{in_scope | out_of_scope, 建议领域, 置信度, 理由}`，输入输出原样打印（群 + 仪表盘）。
- **reasoning-blind**：照抄 Claude Code auto mode 原则——只看原始输入，不采信 agent 自己的辩护/自辩。
- **不设规则短路层**：这是语义判断，没有白名单类东西可依；区别于命令黑白名单场景。
- **Plan B（降本备选，未采用）**：严格指判别式模型。现状不可用——JEV 是闭源 API 无本地权重；laya 是 3 天新仓库、自承校准失效，需实测才可采信。明确排除「小生成式模型」作为 Plan B 的定义。

## 与 research 结论的张力（显式裁决）

`docs/research/drift-detection-models.md` 的明确推荐是**路线三：NLI/cross-encoder 小模型 + 规则自组装**（毫秒级、零边际成本、离线、可解释四约束下唯一全满足），并给了「规则短路 → 小模型 → 置信度门控」的三层混合形态。**该结论未被采纳为已定路线**，最终选 Plan A（LLM 判定），理由记录在源 issue：

- **可演示**：LLM 判定在演示里即时可用，自组装路线需微调 + 标注 + 阈值调参，MVP 时间盒内做不完。
- **投屏可证输入无历史**：判定输入输出原样投屏，评委当场能看到输入只有 `{目标, 新消息}`——这是漂移注入环节的胜负手（`docs/PRD.md` §7）。
- **现成开源无任务漂移件**：research 路线三自己也确认「未找到任何现成的任务漂移检测开源实现」，相邻组件（NLI、Prompt Guard）无人为 agent 任务漂移场景微调过，开箱效果存疑。

research 四约束中的「毫秒级 / 零边际成本 / 离线」是**被放宽的约束**：用户从未要求离线或零边际成本，允许调用 LLM API（见 issue 正文）。**后人请勿把 `drift-detection-models.md` 的推荐当成已定架构**——它是证据文档，裁决在本 ADR 与源 issue。

## Considered Options

- **Plan A：独立无状态 LLM 判定（采纳）**——可演示、投屏可证、零集成成本；代价是有 API 边际成本、非毫秒级。
- **Plan B：判别式模型（备选）**——理论成本/延迟最优，但 JEV 闭源、laya 不成熟，均不可直接采信；降本时再实测重启。
- **规则短路层 / 白名单（否决）**——语义判断无白名单可依，规则层在此场景是伪需求。
- **research 路线三：NLI 自组装（否决为 P0 路线）**——约束被放宽后不再紧迫，细节见上节。
- **主模型自判（否决）**——违反 reasoning-blind，agent 可自辩说服判定器。

## Consequences

- 守卫通路依赖模型 API：不可用时按 PRD §7 故障剧本②处理（放行 + 「⚠ 未判定」徽标 + 留痕），守卫是语义第二意见、不是安全边界。
- Plan B 若未来启用，接口不变（输入输出契约固定），只换判定实现——这正是把网络/判定层做成可替换接口的回报。
