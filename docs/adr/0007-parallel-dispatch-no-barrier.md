# 1:N 派遣无 barrier：完成即回收、成员级独立结算、退群即消失

1:N 派遣的编排语义此前未定（谁等谁、交接文档共享还是各拿、失败怎么算、退群怎么画）。我们决定：同群成员互见但派遣只能摇新成员；交接文档输入/输出每人一份；完成即回收、系统不设汇聚点；失败成员级独立结算；补派默认人工审核；退群从成员表与网络图直接消失、不建历史图。深度 × 并发的数值口径已进 `CONTEXT.md`，此处只记 why。

## Status

accepted

## Decision

- **互见但派遣只能摇新成员**
  - 同群成员互见：agent 间通信 = SendMessage + ListAgents，不是 @ / steering。
  - 已在群的成员不可被"再派"——不产生新上下文窗口，违背任务级隔离。
  - B 摇新帮手 E → E 深度 = B 深度 + 1，正常计链；"互相派遣是否加深"消解为：不存在给老成员加深的动作。
- **交接文档输入每人一份、输出每人一份**
  - 三人任务不同，派遣者为每个被派者各生成一份 handoff；退出群聊**前**各自交回一份终版（七节骨架、照 #15 模板）。
  - 过程 SendMessage 不替代终版交接。
  - 派遣者已先退群时，接收方 = 最近活跃祖先，一路无祖先兜底主人（#24 评论追加，源自 #31 跳级挂靠同一条规则）。
- **完成即回收、无 barrier**
  - 谁交回 handoff 谁先退群，系统不设汇聚点，派遣者不强制等齐。
  - 派遣者是否阻塞由其会话自行决定：自己的活不受阻就继续干；需要成员成果才能推进则挂起——**等待状态 = idle 蓝**（归入"此刻无活跃计算"）。
- **失败成员级独立结算**
  - 部分成功即成功，不整批回滚；其余成员照常完成即回收，跨机器互不影响。
  - 异常退群 ≤5s 消失 + 任务回待领取 @主人（#18 口径）；无终版 handoff = 没有（fail-closed，不猜）。
- **补派固定人工审核（#41 修订）**
  - 本轮不提供自动补派个人设置；成员异常退群后任务进入待领取，由主人或获授权者人工补派。
  - 该口径不影响同一次派遣中 spawn 失败最多一次的自动重试；两者是不同机制。
- **退群 = 直接消失、不建历史图**
  - 成员 = 活进程，成员表与派遣网络图直接移除；历史唯一载体 = 群消息流（派遣事件 + 退群消息按时间排）。
  - **推翻 #17 遗迹规格**（去饱和 + 虚线环 + "退群 HH:MM" + 冻帧全部作废），执行方案与文件清单见 #28。
- **深度 × 并发独立相乘**：默认 3 × 5 → 峰值 31 活跃成员。
  数值与词条见 `CONTEXT.md`（派遣深度 / 派遣并发 / 补派 / 回收），本 ADR 不复读。

## Considered Options

- **整批 barrier 等齐（否决）**：快成员被迫挂着等慢成员，与"完成即回收"的摇人节奏冲突，也堵死派遣者边干边等的自由。
- **共享一份交接文档（否决）**：任务不同则谁写、写在哪全成问题；共享暗示共享上下文，撞第一性原理"绝不共享上下文"。
- **整批失败回滚（否决）**：一个成员挂了拖死全批，跨机器场景下回滚无处安放；成员级独立结算才能部分成功即成功。
- **自动补派为默认（否决）**：静默重摇烧钱、掩盖故障；故障剧本需要"任务回待领取 @主人"这一步人为可见。
- **冻结槽位 / 退出过渡（否决）**：等于在图上留隐性历史图，与"图上只有活跃成员"正面冲突；接受节点硬删的布局跳变（#28 R3）。
