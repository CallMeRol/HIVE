为什么头像位不放精灵

  • 头像位是圆形：精灵四角会被切，圆边抗锯齿还会把像素糊掉。
  • 两个组件尺寸不一致（30 vs 32）：32×32 母版缩到 30 是 1.067×，非整数倍 → 抽样不均。
  • 头像要表达"这是谁"（会话目标派生的名字），精灵要表达"它现在什么状态"——合成一个通道会一起丢信息。
  • 所以：头像 = 名字 + 右下角状态点；精灵 = 网络图节点槽 + 仪表盘卡片（方形 + 色环）。
演示三段叙事：成员表（谁在） → 派遣网络图（谁派的谁 + 谁快垮了） → 卡片（单个成员的上下文窗口占用）。

5 · 交付验收 tachikoma.png / .json 能不能被读进来

契约要求的导出命令（Aseprite）

aseprite -b tachikoma.aseprite \
  --list-tags \
  --sheet tachikoma.png --data tachikoma.json \
  --format json-array \
  --sheet-type horizontal \
  --shape-padding 0 --inner-padding 0 --border-padding 0

# 美术自检用（不是交付格式）：
aseprite -b tachikoma.aseprite --save-as 'tachikoma-{tag}.gif'
--list-tags 是必须的：不加就没有 meta.frameTags，播放器不知道播哪几帧。--trim / --extrude / padding 必须关或 0。
