# Issue #42 实现记录

## 目标

将 #41 已裁定的产品与架构口径落入仓库，使后续并行实现共享同一套完成定义、领域词汇、事件契约和所有权边界。

## 决策

- 使用独立分支 `issue-42-authoritative-spec-contracts`，避免原工作区大量未跟踪调研与设计资产混入提交。
- 以 #41 为本轮产品行为总规格；`CONTEXT.md` 只保留领域词汇，不承载协议字段或模块布局。
- 将产品完成定义放在 PRD，将跨模块事件与所有权放在独立开发契约中；ADR 只保留难逆、存在真实取舍的工程决策。
- 历史研究与设计稿不自动成为权威输入；只纳入满足 #42 验收所必需、且能明确标注权威层级的文件。
- 发现 `hive.afk-issue-42` 中已有同票未提交草稿和通过记录；选择复用其契约结构与验收脚本，再合并本轮补充，而不是维护第二套互斥契约。
- 通用图引擎明确选用 Vue 3 原生的 Vue Flow `@vue-flow/core`。原研究推荐的 `@xyflow/react` 与 vendored Vue renderer 不兼容；Vue Flow 官方能力覆盖自定义节点/边、缩放、平移和选择，Hive 只保留业务布局层。

## 已发现的冲突

- 旧 `CONTEXT.md` 将越界定义为“连续两次越界才触发派遣”；#41 已裁定为单次 `out_of_scope` 立即派遣。
- `ADR-0007` 将异常后的自动补派描述为主人可配置；#41 已裁定异常补派默认且本轮固定为人工审核，只有 spawn 失败可自动重试一次。
- `ADR-0001` 标题和正文使用 GitHub fork 口径；`ADR-0003` 已裁定 snapshot vendor，需显式标注替代关系，防止实现者误用旧口径。
